## 源码边界与容量上限

[单文件搜索](../Sources/SearchEngine.swift)已经限制查询为 4,096 个 UTF-16 单元、文档为 800 万单元、结果为 50,000 个匹配/200,000 个捕获范围；使用 ICU 进度回调检查 0.5 秒预算、取消及只保留最新请求的 worker。再次仅实现“后台搜索”会重复已有工作，更多病态正则的专项验收仍需单独执行。

[项目搜索](../Sources/ProjectSearch.swift)限制为 50,000 文件、单文件 2 MiB、总读取 128 MiB、2,000 个结果；严格解码磁盘字节，跳过二进制和不可读输入。扩展流程时必须保留部分结果及跳过文件的说明。跨文件替换之前先加入缓冲区修订及共用忽略规则，不能承诺跨文件原子撤销。

[文件打开](../Sources/EditorUI.swift)同步调用文档所有者的打开操作。选择异步读取或新文本存储模型前，应测大文件打开/编辑成本；只把读取移出主队列不能消除解码、文本存储安装或布局成本。

当前生产 Swift 共 9,298 行，`EditorUI.swift` 占 4,472 行，约 48%。这说明维护职责集中，不是实测性能缺陷。应保留文档拥有文本/磁盘设置、修订检查及工作区拥有任务的边界，避免无依据的大规模重写。

## 实施顺序与完成门禁

1. 解决两项当前 UI 失败，完成完整 UI 门禁及真实输入/文件面板矩阵。每次运行行为修改按[开发交付流程](development.zh-CN.md)安装和验证。
2. 增加共用项目包含/忽略规则与未保存缓冲区搜索；范围、完整性和修订可信后，再实现项目正则/替换。
3. 增加显式格式化、编译错误导航和一个可选 LSP；Git diff 复用磁盘/缓冲区审阅边界。
4. 按实际笔记工作场景完善 Markdown 分享/导航和无障碍。
5. 测持续工作负载、验证原生平台；功能验收完成后再准备签名发行及支持的更新政策。

每项实现采用聚焦 Conventional Commit、双语文档、影响范围内的检查和保留证据。跨模块/发布适合完整门禁，每次小修改无须跑全部套件。已验收的运行行为修改还需保留草稿并正常退出、备份安装、重新启动，核对安装版本/路径/程序摘要。
